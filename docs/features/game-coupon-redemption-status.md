## 1. 业务上下文与页面流

### 1.1 业务背景
登录用户需要按当前选中的托管账号查看每个券码的持久化兑换情况，同时看到收录日期；游客不展示云端状态。

### 1.2 页面流与路由
仅修改现有页 `subPackages/tools/game-coupons/index`，不新增路由及入口。

## 2. 前后端 API 契约

复用 `GET /game-coupons/{gameId}/codes`。查询参数增加账号数据库 ID 列表 `accountIds`；券码响应项可含 `createdAt` 与 `redeemedAccountIds`。由于 Apifox 生成层受仓库规则保护，本次业务页在本地扩展类型表达此次接口契约，不手改生成文件。

## 3. 交互约束

- 登录用户按当前勾选的托管账号 ID 查询；账号切换和手动刷新均重新查询。
- 游客不传 `accountIds`，不展示持久化兑换状态。
- 只在选中账号范围内汇总 `redeemedAccountIds`：全已兑显示“已兑换”，部分已兑显示“部分已兑换”，全未兑显示“未兑换”。
- 展示 `createdAt` 日期；无有效时间不展示日期占位。
- 初次加载默认只选一个目标：优先后端默认托管账号，其次首个托管账号，再次首个本地账号；新增游客账号时仅选中新账号。用户仍可主动多选。
- 底部操作栏展示账号数 × 券码数；组合数达到 6 组时二次确认，取消可返回检查。
- 兑换结束使用轻提示；页面结果卡提供完整明细展开入口，兑换记录原展示不变。
- 兑换提交仍传所选账号与券码，由后端逐账号×券码防重。
